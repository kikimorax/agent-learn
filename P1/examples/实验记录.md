- 判断与结论：待填写；分别记录格式、遗漏和新增或改错的事实，限长成功不等于信息完整。

### 历史记录：旧图书馆案例的终端编码问题

以下保留当时的输入、输出及排查记录，不作为新案例的运行结果。当前课程已改为运行 Python 源文件。

- 日期与课次：2026-09-23，P1-01
- 执行目录与命令：P1 目录；heredoc 管道方式 `@'...'@ | uv run python -`，在终端里直接粘贴运行
- 模式：真实模型（本地代理）
- 固定输入：图书馆文本"图书馆周一闭馆；周二至周日 9:00–17:00 开放；借书需读者证，不支持校外借阅。"
- Prompt："总结这段文字：" + text
- 实际结果（模型原样返回）：

  > 消息显示为乱码，无法准确判断问题。
  >
  > 请重新发送，并尽量写清：
  > - 想计算什么
  > - "30"指什么
  > - 时间范围是否是 9:00-17:00
  > - 需要的结果格式
  >
  > 例如可直接发：
  > - 30 天里，按 9:00-17:00 计算，一共多少小时？
  > - 30 分钟后是否在 9:00-17:00 范围内？
  >
  > 已说明消息乱码，请重发问题。

- 判断：失败，但原因不是 Prompt 质量或模型能力，而是**终端编码问题**：部分 PowerShell 终端（尤其是 VS Code 的 PowerShell Extension 内置终端）里，heredoc 通过管道 `| uv run python -` 传输中文时，若该终端的 `$OutputEncoding` / 控制台代码页不是 UTF-8，中文和特殊符号会在到达 Python 进程之前被替换成 `?` 或损坏；模型收到的确实是乱码文本，如实报告"无法识别"。
- 复现与验证：
  1. 在普通 `pwsh` 终端里打印 `repr(prompt)` 和 `prompt.encode("utf-8")`，确认程序侧构造的字符串本身完整、正确。
  2. 同样的 heredoc 命令换到 `PowerShell Extension` 终端执行，模型返回乱码提示，证实问题出在该终端向子进程传递 stdin 内容的编码环节，不是 Python 代码或 Prompt 本身。
- 结论：不要用 heredoc + 管道方式在编码设置未知的终端里传送中文 Prompt；改为把代码写成文件（如 `examples/scratch_p1_01.py`），用 `uv run python examples\scratch_p1_01.py` 直接运行。Python 读取源文件默认按 UTF-8 解码，不受终端控制台编码影响，规避了这整类问题。
