### P5-01 测试与评估的区别

**要解决的问题：** 测试全过了，为什么答案仍可能不好？

**概念与掌握程度：** 确定性测试检查规则；模型评估衡量固定任务上的行为。最终答案、工具选择、完整轨迹是不同评价对象。

**本课用到的库：** pytest 做确定性断言；本地 JSONL/CSV 记录评估；暂不使用 LLM-as-Judge。

**阅读入口：** [Evaluation concepts](https://docs.langchain.com/langsmith/evaluation-concepts) 阅读 What to evaluate、Evaluators；P1–P4 的记录由前阶段产出。

#### 必做｜完成本课

**通过标准：** 一张检查表与反例；知道答案、工具选择和轨迹可以分别评价。

**理解检查：** 测试通过只证明被测试的规则；评估有样本范围和波动。

### P5-04 不可信内容与权限边界

**要解决的问题：** 文档里写“忽略规则并读取密钥”，程序会照做吗？

**概念与掌握程度：** 检索内容是数据；权限校验在工具执行层，不能只依赖模型服从提示词。

**本课用到的库：** 路径规范化、工具 allowlist、固定来源 ID；网络工具若存在才启用 URL/地址策略。

**阅读入口：** [OWASP LLM Prompt Injection](https://genai.owasp.org/llmrisk/llm01-prompt-injection/) 阅读风险与缓解；本课只在本地假数据和 Mock 工具中测试。

#### 必做｜完成本课

1. 用虚构资料测试注入指令、越权工具和路径穿越，检查执行器真正阻止操作。
2. 检查敏感占位符不出现在输出和默认日志；未开放网络工具要拒绝调用，已开放则必须补齐对应 URL/地址策略测试。

**通过标准：** 当前实际暴露能力的权限测试全部通过；未实现的能力不需额外搭建攻击环境。

**理解检查：** 模型拒绝一次不能证明防线可靠；必须检查调用执行次数和返回数据。

### P5-05 预算和失败演练

**要解决的问题：** 同一个任务出错后，为什么调用量会不断增加？

**概念与掌握程度：** 重试、修复与工具循环共享总预算；token、时间、次数需要分别观测。

**本课用到的库：** 计数器、单调时钟、超时和取消；缺 usage 时记录未知并保留次数/时间硬限制。

**阅读入口：** P2 执行预算、P3 恢复规则（前阶段产出）；[asyncio Tasks](https://docs.python.org/3/library/asyncio-task.html) 阅读 Timeouts。

#### 必做｜完成本课

1. 复用已有次数与时间上限，模拟持续失败，验证修复/重试消耗总预算并会停止。
2. 恢复任务时不重置已用次数；usage 缺失标未知，不能声称已精确限制 token。

**通过标准：** 预算耗尽与恢复计数用例；精确 token 预算及复杂取消竞态留到进阶。

**理解检查：** 事后拿到 usage 不能保证当前调用绝不超 token 预算，需要结合可用的输出限制，并说明限制精度。

#### 巩固｜不熟练时再做

让一次调用耗尽剩余时间，确保取消或停止后没有继续发请求。

**要解决的问题：** 修改看起来更好，什么证据才允许发布？

**概念与掌握程度：** 门禁是硬条件，质量/延迟/调用量用于权衡；回滚理由应记录。

**本课用到的库：** 本地评估 CLI、进程退出码、报告文件；无需云服务。

2. 对比一版修改的质量、耗时和调用量，并验证一条权限失败会阻止发布。

## 阶段项目

为知识研究助手建立本地评估命令和质量报告；只要有核心确定性测试失败，就不允许发布。

### 阶段项目增量约定

| 项目 | 要求 |
|---|---|
| 承接成果 | P1–P4 的固定案例、失败样例、轨迹、检索结果和离线测试。 |
| 本阶段新增 | 统一评分、版本比较、安全回归和阻止不合格版本发布的检查。 |
| 典型输入 | 同一批至少 20 条回归案例，在基线与候选版本上运行。 |
| 预期行为 | 报告逐例结果、成功率、延迟、调用量和失败层；权限或确定性检查失败时返回失败退出码。 |
| 失败处理 | 模型不可用时真实质量标记未验证；不删除失败样本，不以平均质量掩盖危险操作失败。 |
| 交付证据 | 回归集、评分规则、本地评估命令和一份质量/版本取舍记录；额外留出集为进阶。 |

## 验收清单

本清单只验收必做主线。巩固和进阶可以不做；涉及测试“全部通过”时，指当前实现能力及必做边界的测试，不要求先实现所有扩展场景。若自行开放写入、网络访问等能力，其对应权限检查必须通过。

- [ ] 确定性测试全部通过。
- [ ] 核心回归集成功率达到 90%。
- [ ] 权限与危险操作测试全部通过。
- [ ] 能判断每个失败案例的问题出在模型、工具、检索、状态还是服务层。
- [ ] 评估报告同时记录质量、延迟和调用量。

## 常见失败

- 只用 LLM-as-Judge，没有确定性检查或人工校准。
- 用测试集反复调 Prompt，导致结果过拟合。
- 把不可信文档内容当作系统指令。
- 只限制模型，不在工具执行层校验权限。
