### P6-02 输入校验与错误映射

**要解决的问题：** 请求字段错了与模型超时，应该返回同一种错误吗？

**本课用到的库：** Depends、HTTPException、异常处理器、Pydantic；TestClient 替换依赖。

### P6-03 SSE 与事件顺序

**要解决的问题：** 怎样把工作流进度和模型文字一起发给客户端？

**概念与掌握程度：** 模型 token 增量、Agent 步骤事件、HTTP SSE 传输属于不同层。

**本课用到的库：** StreamingResponse、异步迭代器；SSE 的 event/data 与空行分帧。

**阅读入口：** [Starlette Responses](https://www.starlette.io/responses/) 阅读 StreamingResponse；[SSE 标准](https://html.spec.whatwg.org/multipage/server-sent-events.html) 阅读 Parsing an event stream、Interpreting an event stream。

#### 必做｜完成本课

1. 提供流式接口，将真实文本增量与完成事件转成 SSE；先用固定事件测试。
2. 注入中途错误，错误后不得再发送成功事件；能够按帧解析。

**通过标准：** 一份真实序列及正常/错误终止测试；暂不做复杂跨块编码演练。

**理解检查：** 普通 JSON 响应切成字符不是模型流式验证；终止事件不可重复，错误后不得再发成功。

#### 巩固｜不熟练时再做

把中文和换行放在跨网络块的内容中，验证按 SSE 帧解析而非假定一块就是一条事件。

### P6-04 断开、取消和并发限制

**本课用到的库：** asyncio 取消、Semaphore、finally 清理；请求断开检测；可控假模型。

**阅读入口：** [asyncio Tasks](https://docs.python.org/3/library/asyncio-task.html) 阅读 Task cancellation、Timeouts；上一课流式实现（待实现）。

**通过标准：** 取消、超时及并发上限有可控测试；多种清理异常和竞态留到进阶。

**理解检查：** 取消不等于已经回滚远端副作用；写操作仍依赖 P3 的幂等策略。

### P6-05 PostgreSQL 持久化与恢复

**要解决的问题：** 多进程服务怎样共享和恢复任务状态？

**概念与掌握程度：** 进程内对象不能跨实例持久化；数据库保存检查点，thread、request 和幂等操作标识用途不同。

**本课用到的库：** PostgreSQL Checkpointer、数据库连接生命周期；复用 P3 恢复逻辑。

**阅读入口：** [Add memory](https://docs.langchain.com/oss/python/langgraph/add-memory) 阅读 Use in production 的数据库检查点示例；[Persistence](https://docs.langchain.com/oss/python/langgraph/persistence)。

#### 必做｜完成本课

1. 把新会话接入 PostgreSQL 检查点，保留 SQLite 历史，不做旧数据迁移。
2. 重启 API 后用原 thread 恢复；新 thread 隔离，数据库不可用明确失败。

**通过标准：** 新会话持久化与恢复证据；旧会话迁移、多实例协调属于进阶。

**理解检查：** 课程默认旧 SQLite 历史保留为只读证据，新会话进入 PostgreSQL；如需迁移旧会话，先单独设计和验证导入。

### P6-06 日志、认证和脱敏

**要解决的问题：** 怎样查慢请求，又不把用户资料全写进日志？

**概念与掌握程度：** request_id 关联一次请求，thread_id 关联会话；日志、Trace 和汇总指标分别服务排错与趋势分析。

**本课用到的库：** logging、请求中间件、认证依赖；本地 JSON 日志及耗时汇总。

**阅读入口：** FastAPI Dependencies 的依赖注入示例；P5 权限与敏感信息测试；本课不要求部署云观测平台。

#### 必做｜完成本课

2. 用敏感占位符检查默认日志不写密钥、完整 Prompt 和资料正文。

**通过标准：** 一次请求的分层日志、认证与脱敏测试；额外频率策略和观测组件不强制。

**理解检查：** 可观测不等于保存所有内容；日志既要关联到失败，也要限制记录范围。

### P6-08 故障与重启演练

**要解决的问题：** 服务在用户请求中途出错，能否恢复并解释结果？

**概念与掌握程度：** 部署验收覆盖成功、故障、恢复；质量门禁随服务一起保留。

## 阶段项目

用 Docker Compose 启动 Agent API、PostgreSQL 和 Qdrant；提供健康检查、流式聊天、会话恢复和本地日志。独立观测组件为进阶。

### 阶段项目增量约定

| 项目 | 要求 |
|---|---|
| 承接成果 | 通过 P5 检查的工作流、评估命令、配置和状态边界。 |
| 本阶段新增 | 普通 API、SSE、请求关联、认证、PostgreSQL 状态和容器化运行。 |
| 典型输入 | 合法聊天请求、流式请求、未认证请求；带原 thread_id 的恢复请求。 |
| 预期行为 | 普通响应符合约定；SSE 有真实事件与终止信号；重启后恢复会话和知识库。 |
| 失败处理 | 非法输入和依赖错误映射明确；断开后释放资源；数据库不可用不静默切回内存。 |
| 交付证据 | API/事件约定、自动化测试、Compose、配置样例、持久化和故障日志、本地耗时报告。 |

## 验收清单

本清单只验收必做主线。巩固和进阶可以不做；涉及测试“全部通过”时，指当前实现能力及必做边界的测试，不要求先实现所有扩展场景。若自行开放写入、网络访问等能力，其对应权限检查必须通过。

- [ ] 普通响应、SSE、健康检查和错误响应都有自动化测试。
- [ ] 日志能用请求 ID 关联模型、工具、检索和持久化步骤。
- [ ] 容器重启后知识库和会话状态仍存在。
- [ ] 密钥、完整 Prompt 和敏感文档不会默认写入日志。
- [ ] 已记录端到端延迟和单任务调用量，其中包含本地代理的耗时。

## 常见失败

- SSE 只是把最终答案拆成字符发送，并非转发真实事件。
- 客户端断开后后台调用仍无限运行。
- 只把数据保存在进程内存中，却当作生产环境的持久化方案。
- 容器能启动，但没有健康检查和恢复验证。
