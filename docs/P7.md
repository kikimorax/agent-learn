### P7-04 性能测量

**要解决的问题：** 用户觉得慢，是模型、检索还是数据库的问题？

**概念与掌握程度：** 均值可能掩盖慢请求；测量需明确并发、样本数、冷热缓存和失败处理。

**本课用到的库：** perf_counter、结构化日志、本地统计脚本。

**阅读入口：** P6 分层耗时和 P5 固定数据集（前阶段产出）。

#### 必做｜完成本课

1. 使用已有分层日志记录固定任务的总耗时、首文本耗时和调用量，保留逐请求明细。
2. 分析最慢或失败的一条，说明时间主要花在哪里。

**通过标准：** 真实明细与简短瓶颈解释；多轮压测、p95 优化对照归入进阶。

**理解检查：** 不要删慢请求提高均值；预热前后分别记录，代理耗时包含在用户总耗时内。

#### 巩固｜不熟练时再做

挑一条最慢请求，按日志分解时间并说明未解释部分。

沿用本课输入或换一个小例子，能独立完成即可；不新增强制报告，不阻塞进入下一课。

## 验收清单

本清单只验收必做主线。巩固和进阶可以不做；涉及测试“全部通过”时，指当前实现能力及必做边界的测试，不要求先实现所有扩展场景。若自行开放写入、网络访问等能力，其对应权限检查必须通过。

- [ ] 新环境可根据文档完成安装和启动。
- [ ] 确定性测试、权限测试和核心回归检查全部达到要求。
- [ ] 能演示一次成功路径和至少三类失败恢复路径，可复用 P2–P6 已有用例与记录。
- [ ] 已记录检索质量、端到端延迟和单任务调用量。
- [ ] 能解释为什么核心实现没有默认采用 Multi-Agent。

## 常见失败

- 演示只覆盖理想输入。
- 按 README 操作仍需依赖未写入文档的本机配置。
- 指标只展示平均值，不保留慢请求和错误原因。
- 架构图与代码实际的状态流转不一致。

## 复盘问题

1. 当前最限制质量的是模型、数据、工具还是工作流？
2. 下一次迭代应增加能力、降低复杂度还是改善评估数据？
