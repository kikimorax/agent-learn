### P0-04 HTTP、JSON 和异常

**要解决的问题：** HTTP 200 为什么也可能不是可用答案？

**概念与掌握程度：** 传输成功、JSON 解析成功、业务成功是三层；超时与 4xx/5xx 分开处理。

**本课用到的库：** httpx.Response、raise_for_status、HTTPError；json 解析；logging 记录阶段和错误类型。

**阅读入口：** [HTTP 示例](../P0/examples/http_request_demo.py) 的 safe_request、safe_json；[HTTPX Mock transports](https://www.python-httpx.org/advanced/transports/) 阅读 Mock transports。

#### 必做｜完成本课

2. 再模拟 200 非 JSON 与 502 空响应，分别归类，不将它们当正常答案。

**通过标准：** 用例能区分传输、解析和业务结果；说明超时与 HTTP 错误的区别。

**理解检查：** 收到 HTTP 响应只能说明有 HTTP 服务响应，不能证明模型生成成功。

### P0-06 同步、异步和并发

**要解决的问题：** 写了 async 为什么不一定更快？

**概念与掌握程度：** await 允许等待期间调度其他任务；顺序 await 仍是顺序；并发不等同于 CPU 并行。

**本课用到的库：** httpx.Client、AsyncClient；asyncio.run、gather；perf_counter。

**阅读入口：** [HTTP 示例](../P0/examples/http_request_demo.py) 的三个 fetch 函数；[asyncio Tasks](https://docs.python.org/3/library/asyncio-task.html) 阅读 Running tasks concurrently。

**通过标准：** 保存三种结果；能解释顺序 await 为什么不等于并发。

**理解检查：** 网络波动与失败会影响时间，不能只取最快一次；异步顺序不保证提速。

## 阶段项目

交付一个读取 `LLM_BASE_URL`、`LLM_MODEL` 和可选 `LLM_API_KEY` 的 CLI 客户端。代理离线时给出有助于排查问题的错误提示，在线时能完成多轮文本对话。

### 阶段项目增量约定

| 项目 | 要求 |
|---|---|
| 承接成果 | 基础 Python 与命令行；不依赖前一阶段项目。 |
| 本阶段新增 | 统一配置、模型 HTTP 调用、错误分类、多轮 CLI 和能力报告。 |
| 典型输入 | CLI 第一轮输入“我叫小林”，第二轮问“我叫什么”；能力探针读取实际代理配置。 |
| 预期行为 | CLI 能利用历史回复；探针逐项给出证据、错误或未知状态，不将 HTTP 可达等同于模型可用。 |
| 失败处理 | 缺配置时说明缺少变量；连接失败或超时时给出错误；非文本项和非法响应不会被误当答案。 |
| 交付证据 | 可运行 CLI、能力报告、配置/错误测试及排错记录。 |

## 常见失败

- 把代理地址、模型名或密钥写死在多个脚本中。
- 只判断状态码，不检查响应结构。
- 捕获所有异常后静默返回空字符串。
- 代理尚未实现某项能力，却把因此出现的客户端报错归因于 Prompt。
