# Agent 开发学习课程大纲

> 从读写基础 Python 代码开始，学习独立设计、评估和部署可靠的 AI Agent。

## 1. 课程定位

**适合人群：** 已能看懂并修改基础 Python/API 代码，但对测试、类型、异步、LLM 应用工程还不熟悉的学习者。

**核心目标：** 用 26 周时间，每周学习 8–9 小时，最终独立交付一个可测试、可观测、可恢复，并设有安全边界的“知识研究助手”。

**主线技术栈：** Python 3.12、OpenAI 兼容接口、LangChain、LangGraph、Pydantic、pytest、FastAPI、Qdrant、PostgreSQL、Docker。

**运行约束：** 聊天模型只连接本地 OpenAI 兼容代理。Embedding、向量数据库、日志和数据库采用本地方案；LangSmith 等云服务只作为选学内容。

课程遵循以下顺序：

```text
Python 工程基础
    ↓
LLM 应用与可验证 Prompt
    ↓
工具调用与单 Agent
    ↓
LangGraph 状态化工作流
    ↓
RAG 与事实依据
    ↓
评估、安全与可靠性
    ↓
API、部署与运行
    ↓
生产级综合项目
```

Multi-Agent、MCP 和 Code Agent 是进阶选修。只有在单 Agent 或确定性工作流无法满足需求、且评估数据表明更复杂的架构确实有收益时，才引入这类架构。

## 2. 学习与验收规则

### 概念、库和实验分别怎么学

每课先完成 **理解概念 → 阅读最小示例 → 修改并观察 → 用结果验收** 的必做主线；独立练习按熟练程度选做。概念帮助解释现象，库负责实现操作，实验用来检验理解；三者在同一课中配合，不必先学完所有理论或通读整个库。

| 学习层次 | 学到什么程度 | 完成证据 |
|---|---|---|
| 理解概念 | 能用自己的话解释，并指出一个代码中的例子和反例 | 简短说明或数据流图 |
| 使用库 | 会使用本课列出的对象和方法，能查到错误处理方式 | 能运行并修改最小示例 |
| 完成实验 | 固定输入，只改变一个因素，比较并解释结果 | 保留输入、输出和对照记录 |
| 独立实践 | 换一个输入或限制，不照抄答案完成任务 | 自己的练习与失败用例 |
| 阶段交付 | 把前面的必做实验接入贯穿项目 | 可复现项目、测试与评估 |

不要把“读过文档”“运行一次没有报错”“模型恰好回答正确”直接当作掌握。每课都要能说明自己改了什么、结果如何、哪些还不能确定。

<a id="学习优先级"></a>

### 三个层级怎么用

| 层级 | 什么时候做 | 完成要求 | 是否阻塞进入下一阶段 |
|---|---|---|---|
| **必做** | 第一次学习时 | 理解核心概念，完成最小实验与关键失败检查，达到本课通过标准 | 是 |
| **巩固** | 不能独立复现、解释不清时 | 换输入或约束再练一次，沿用原记录 | 否，按实际薄弱点补练 |
| **进阶** | 项目遇到相关需求，或想深入时 | 扩展参数对照、完整异常矩阵、性能优化等 | 否 |

每课都明确列出三个层级。进阶实验默认折叠；首次学习只看必做和通过标准即可。较完整的实验说明保留作参考，重复部分直接复用，不要求重做。

每阶段以**必做课次 + 阶段验收清单**判断完成。选择不做进阶，不影响完成状态；但自己新增了写入、网络访问等能力时，必须落实相应权限与安全检查。原有核心能力和阶段交付保留，不靠跳过基本错误处理来减量。

### 每周节奏

- 2 小时：理解本周概念，按课次阅读指定章节。
- 3 小时：运行或编写最小示例，完成引导实验。
- 2–3 小时：优先完成阶段项目集成；有薄弱点时做巩固练习。
- 1 小时：补充测试、保存结果和复盘。

共 8–9 小时。单课的 1–2 小时是必做主线的参考时间，项目集成另留时间；进阶不计入必修进度。26 周是建议安排，按完成证据推进；遇到失败可以多用一周，不自动勾选验收。

### 每课固定结构

每课先说明问题、核心概念、按需使用的库与阅读入口，再分成必做、巩固、进阶。必做有明确通过标准，巩固用于独立复现，进阶保留较完整的实验参考。各阶段的知识范围和实验索引是导航，不是另一份必做清单。

库的学习范围以当课列出的 API 为限：P0 学 HTTP 与校验，P1 学模型调用与评估，P2 手写工具循环，P3 才正式学习 create_agent 与状态图，P4 学本地检索，P5 学评估和安全检查，P6 学服务与部署，P7 整理交付。底层训练、框架源码和选修内容不作为当前课的前置要求。

### 材料状态与存放位置

- **已有示例**：给出真实文件与函数，可阅读运行；P0/P1 已有部分材料。
- **待实现练习**：文档给步骤和验收，由你在 examples/ 编写；P2–P7 当前主要是这一类。
- **阶段项目**：在 project/ 集成前阶段能力，tests/ 保存离线测试、Fixture 和评估入口。
- 不恢复 exercises/ 目录。练习代码与实验记录仍放 examples/；不把待实现文件写成可以立即执行的命令。

后续阶段开始实现时再初始化对应 uv 项目并安装当课需要的库；P2–P7 当前没有完整依赖和启动脚本，不能直接照搬 P0/P1 的运行命令。模型客户端始终读取公共配置，依照本地代理实际支持的接口练习。代理不支持某能力时，先用 Fixture 学习控制流，真实能力验收保持未验证。

<a id="实验记录"></a>

### 统一实验记录

每阶段在 examples/ 中维护一份实验记录，按课次追加小节；已有分课记录无需合并重写，链接过去即可。P5 汇总已有数据，P7 链接已有测试与报告，不重新建立整套材料。

必做记录只需写清：**执行目录与命令、输入和关键配置、实际结果、通过或失败的依据**。发生问题时补充原因。评估课再增加其要求的指标和分子/分母；不要求每课填写不适用字段。较多数据可以单独保存 JSONL/CSV。

以下是模板，不是已经运行的结果：

# Pn-XX 实验记录

- 要回答的问题：
- 执行目录与命令：

- 配置：模型、端点、采样参数、预算、依赖版本（不写密钥）

模型输出允许波动，不要求逐字一致。确定性检查验证结构和边界，人工或评估规则检查内容；失败样本保留。业务成功、正确拒绝、技术失败分别记录。

### 完成规则

- 未完成的验收项保持 `[ ]`，实际运行并保留证据后才能改为 `[x]`。
- 阶段整体完成状态在本页课程总览标记；各阶段验收清单保留具体证据和个人笔记。
- P0 已完成状态不因新增复习课撤销；新增指南不代表新增实验已经运行。
- 每阶段至少保留一个确定性测试、一个模型行为评估和一个失败场景，可复用并补充前阶段成果，不重复写报告。
- 模型不可用时，确定性测试仍必须使用 Mock 或 Fixture 运行；这不替代真实模型行为评估。
- 改 Prompt、模型、检索或架构前，先建立固定样例基线；改后用相同口径比较。
- 安全与权限检查必须全部通过；模型质量按阶段定义的固定数据集和指标评价，不用一次成功代替验收。

## 4. 进阶选修

### 选修 A — Multi-Agent 与 MCP（2–3 周）

**进入条件：** 已有单 Agent 基线，并能用评估数据说明任务分解、上下文隔离或权限隔离的必要性。

**内容：** Supervisor、Handoff、子图、共享状态、故障隔离、角色边界、MCP Server/Client 与工具授权。

**项目：** 把研究助手拆成研究员、写作者和审阅者三个角色，并与单 Agent 比较成功率、延迟、调用量和可维护性。如果没有可衡量的收益，就保留单 Agent。

### 选修 B — Code Agent（2–3 周）

**进入条件：** 已掌握工具权限、超时、审批、评估和容器化。

**内容：** 文件范围限制、命令 Allowlist、沙箱、补丁、测试、自修复循环、重试上限和失败报告。

**项目：** 构建一个编程助手：只能在指定工作目录内修改 Python 项目，必须运行测试，且不能自行扩大权限。

## 6. 结业标准

- 确定性测试全部通过。
- 核心回归集成功率达到 90%。
- 权限与危险操作测试全部通过。
- 最终项目覆盖：带引用回答、知识库无答案、工具失败、超时重试、危险操作拒绝、会话恢复、流式响应和容器重启。
- 能记录并解释检索质量、端到端延迟和单任务调用量。
- 能从可靠性、复杂度、可维护性和成本四个维度选择确定性工作流、单 Agent 或 Multi-Agent。

课程以这些标准作为结业依据，要求学习者既能调用模型，也能交付完整的 Agent 系统。

## 7. 阅读资料使用说明
