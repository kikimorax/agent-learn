## 目标

在单 Agent 的基础上构建可观察、可暂停、可恢复的有状态工作流，理解高层 Agent 与底层运行时各自负责什么。

## 前置知识

- 已手写并测试单 Agent 工具循环。
- 能区分纯函数、外部读取和有副作用操作。

## 知识范围（优先级见课次）

- LangChain `create_agent` 的模型、工具、Prompt、State 和 Middleware。
- LangGraph `StateGraph`、Node、Edge、Conditional Edge、Reducer 和 `Command`。
- 短期记忆、Thread、Checkpointer 与跨 Thread 长期记忆的区别。
- `interrupt()`、审批、恢复以及节点重新执行带来的幂等要求。
- 事件流、节点级日志和状态快照。
- 针对瞬时错误重试；模型能修复的错误交回模型处理，需要用户修复的错误暂停等待，未知错误则向上抛出。

## 阶段进阶专题（可跳过）

- Functional API。
- Time Travel、Replay 和 Fork。

### P3-04 Thread 与检查点

**要解决的问题：** 同一任务重启后，如何继续而不串到别人的任务？

**本课用到的库：** Checkpointer；本课先用 SQLite；读取状态快照。

**阅读入口：** [Persistence](https://docs.langchain.com/oss/python/langgraph/persistence) 与 [Add memory](https://docs.langchain.com/oss/python/langgraph/add-memory) 阅读短期记忆、数据库检查点、长期记忆；不要求先学 PostgreSQL。

#### 必做｜完成本课

**通过标准：** 重启与隔离证据；不要求实现长期记忆存储。

**理解检查：** 读取检查点和实际恢复执行都要验证；同一用户可能有多个 thread。

## 阶段项目

交付可暂停的研究工作流：用户可审阅研究计划、限制来源或拒绝高成本步骤，随后从已保存的状态继续执行。

### 阶段项目增量约定

| 项目 | 要求 |
|---|---|
| 承接成果 | P2 的原生循环、工具及预算/权限测试；不重写工具业务逻辑。 |
| 本阶段新增 | 规划、路由、审批、持久化、恢复与节点级日志。 |
| 典型输入 | 研究青禾项目；在计划生成后拒绝、同意或把检索预算改为 1。 |
| 预期行为 | 拒绝不搜索；同意按新预算继续；退出进程后可用同一 thread_id 恢复。 |
| 失败处理 | 非法审批不执行；不同 thread 状态隔离；重放和重试不会重复有效副作用。 |
| 交付证据 | 状态图、字段与 Reducer 说明、审批/重启测试、节点轨迹和原有工具回归。 |

## 验收清单

本清单只验收必做主线。巩固和进阶可以不做；涉及测试“全部通过”时，指当前实现能力及必做边界的测试，不要求先实现所有扩展场景。若自行开放写入、网络访问等能力，其对应权限检查必须通过。

- [ ] 能解释 `create_agent` 与自定义 LangGraph 的使用边界。
- [ ] State 只保存原始数据和必要元数据，不保存难以复用的展示文本。
- [ ] Interrupt 前的副作用是幂等的，恢复执行不会重复产生危险结果。
- [ ] 同一 `thread_id` 的任务可以恢复，新 `thread_id` 不会混用已有状态。
- [ ] 能从日志还原一次完整的状态迁移路径。

## 常见失败

- 所有逻辑都塞进一个节点，无法观察或恢复。
- 没有明确 State 字段的 Reducer 规则，导致更新时意外覆盖数据。
- Interrupt 前执行不可重复的副作用。
- 把对话历史、工作流状态和长期用户记忆混为一谈。
