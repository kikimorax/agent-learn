## 目标

搭建本地知识检索流程，并衡量其效果。回答要能引用证据，证据不足时要明确拒答或降级处理。

## 前置知识

- 能把检索能力封装为只读工具。
- 能记录 Agent 的输入、工具轨迹和最终输出。

## 知识范围（优先级见课次）

- Markdown/PDF 加载、清洗、Chunk、元数据和稳定文档 ID。
- 关键词检索基线；Embedding、余弦相似度和向量检索。
- 本地 Embedding 与 Qdrant；Chroma/FAISS 可用于最小实验。
- 稠密、稀疏和混合检索；Top-K 与过滤条件。
- 引用格式、证据覆盖、上下文预算和无答案行为。
- 检索相关性、回答正确性、相关性和忠实度评估。

## 阶段进阶专题（可跳过）

- Reranker、Parent-Child Retrieval、HyDE。
- HNSW 参数和索引调优。

## 实验索引

以下是实验主题导航，不是额外任务；执行与验收以各课的“必做”和阶段验收清单为准。

### P4-03 Embedding 与相似度

**要解决的问题：** 两句话没有相同关键词，如何找到意思相近的资料？

**概念与掌握程度：** Embedding 将文本变成向量，相似度是检索信号，不是事实正确率。理解输入、维度与距离即可。

**本课用到的库：** 本地 SentenceTransformer.encode；向量点积与范数或库的相似度函数。

**阅读入口：** [Sentence Transformers Quickstart](https://sbert.net/docs/quickstart.html) 阅读 Sentence Transformer、Similarity；仅使用本地推理，不上传资料。

#### 必做｜完成本课

1. 用支持中文的本地 embedding 模型编码同义句、无关句及上一课片段，记录模型和维度。
2. 比较一次向量检索与关键词基线，保留未命中例子。

**通过标准：** 相似度与 Top-3 记录；知道向量相似不等于答案正确。

**理解检查：** 不预设同义句必然排第一，实际失败也是结果；模型切换后旧向量不可混用。

### P4-04 Qdrant 存储和重复导入

**要解决的问题：** 每次导入都增加一份相同文档怎么办？

**概念与掌握程度：** 向量、稳定 ID 和 payload 各有用途；重复导入应有确定策略，内容更新要处理旧片段。

**本课用到的库：** QdrantClient、collection、upsert、查询与过滤；先学本地单实例。

**阅读入口：** [Qdrant Points](https://qdrant.tech/documentation/concepts/points/) 阅读 Point IDs、Uploading points；P4-03 的向量（待实现）。

#### 必做｜完成本课

1. 按模型维度建立 Qdrant collection，存向量、稳定 ID 和来源；完成一次检索。
2. 同一资料重复导入两次，确认数量不增长；错误维度明确失败。

**通过标准：** 导入、查询与去重证据；增量更新和旧片段清理留到进阶。

**理解检查：** 稳定 ID 既要避免重复，也要允许更新；不能简单以标题作为唯一键。

### P4-06 上下文与引用

**要解决的问题：** 检索到了正确片段，答案为什么仍然不可信？

**概念与掌握程度：** 检索候选需要筛选与组织；引用应支持具体陈述，而不只是附一个文件名。

**本课用到的库：** 沿用模型客户端；片段 ID 映射；上下文预算检查。

**阅读入口：** P4-05 的 Top-K 输出（待实现）；[Prompt engineering](https://developers.openai.com/api/docs/guides/prompt-engineering) 阅读 Include relevant context；本课不学习复杂 RAG 封装。

#### 必做｜完成本课

1. 给模型传入相关片段及来源 ID，让答案引用支持它的片段，逐句核对。
2. 注入不存在的引用 ID，阻止将其作为有效证据发布；为输入设置基本长度预算。

**通过标准：** 陈述与片段对应表及虚构引用失败用例；知道预算单位的限制。

**理解检查：** 引用存在性可自动检查，是否真正支持结论仍需内容核对；字符预算只能作为本地近似，不能冒称精确 token。

**本课用到的库：** Fixture、检索结果和回答检查；不增加新库。

**阅读入口：** 前课引用流水线（待实现）；阅读自己标注的原始资料，先写预期行为。

### P4-08 接入工作流并评估

**要解决的问题：** 如何让 P3 的搜索节点使用本地知识库？

**概念与掌握程度：** 保持工作流的审批和预算不变，替换取资料的实现；分别评估检索与回答。

**本课用到的库：** 复用 P3 StateGraph、P4 检索器和来源结构。

**阅读入口：** [项目要求](../P4/project/README.md) 与前七课成果（待实现）。

#### 必做｜完成本课

1. 把检索接到 P3 搜索节点，保留审批与预算，用固定问题检查引用和无答案行为。
2. 重复导入后复跑原问题集，核对来源不重复。

**通过标准：** 可检索 Markdown/PDF 的助手及一份检索/回答基线，复用前课记录。

**理解检查：** 语言流畅不能替代事实评分；只有基线证明瓶颈后才选学 Reranker 或 HyDE。

#### 巩固｜不熟练时再做

选择一个失败案例，定位是切块、检索、上下文还是生成问题，只修改该环节后对照。

沿用本课输入或换一个小例子，能独立完成即可；不新增强制报告，不阻塞进入下一课。

## 阶段项目

将 RAG 接入研究工作流：回答必须包含可定位到文件和片段的引用；证据不足时说明缺少哪些依据，不补写没有依据的结论。

### 阶段项目增量约定

| 项目 | 要求 |
|---|---|
| 承接成果 | P3 的研究工作流、只读工具边界、审批和预算。 |
| 本阶段新增 | 本地 Markdown/文本 PDF 检索、可定位引用、证据不足与冲突处理。 |
| 典型输入 | “青禾预算是多少？请给出处。”以及资料不存在答案或相互冲突的问题。 |
| 预期行为 | 每个事实有支持它的片段和来源；不足时说明缺失依据；冲突时列出相互矛盾的来源。 |
| 失败处理 | 无法提取的 PDF 明确报错；重复导入不累积重复记录；检索不到不等于资料明确否定。 |
| 交付证据 | 文档与元数据、导入/检索实现、引用映射、固定问题集、检索与回答质量报告。 |

## 验收清单

本清单只验收必做主线。巩固和进阶可以不做；涉及测试“全部通过”时，指当前实现能力及必做边界的测试，不要求先实现所有扩展场景。若自行开放写入、网络访问等能力，其对应权限检查必须通过。

- [ ] 文档可以重复导入，且重复记录的数量受到控制。
- [ ] 能展示检索结果如何支持最终答案中的具体陈述。
- [ ] 有固定问题集和检索/回答基线。
- [ ] 能区分“没有检索到”和“资料明确表示没有”。
- [ ] 只有基线结果表明确有需要时，才加入 Reranker、HyDE 等复杂方案。

## 常见失败

- 还没有建立基线，就采用复杂的检索方案。
- Chunk 丢失标题、文件名、页码等引用元数据。
- 把所有 Top-K 内容塞进 Prompt，不管理上下文预算。
- 用最终回答的流畅度代替检索质量评价。
